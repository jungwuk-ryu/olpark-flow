# 길 데이터와 계산 가정값: 방법과 근거 (팀원 B)

계산 엔진이 쓰는 `network.json`·`routes.json`·`parking.json`·`assumptions.json`을 어떻게 만들었고, 숫자마다 근거가 무엇인지 정리한다. 현장 실측은 하지 않았고, 모든 길 폭은 항공영상 판독값이라 `source: "가정"`이다.

## 1. 데이터 출처

| OpenStreetMap 보행로·지하철 출입구 (© OpenStreetMap contributors, ODbL) | Overpass API | 길 연결, 길이, 역 출입구 위치 |

| 서울시 지하철 역별 일별 승하차 (2023.1~2025.12) | 서울 열린데이터광장 | 방면 비율 검증 |

## 2. 경로 (routes.json)

1. Overpass로 공원 일대 보행로를 받는다 (`geo/osm/overpass-query.txt`).
2. 최단 거리만 쓰면 숲속 샛길·주차장 통로를 지나는 경로가 나와서, 길 종류별 비용을 둔다 (`geo/osm/build-skeleton.mjs`의 `COST`).
   - 광장·보행자 도로 0.8, 보도 1.0, 자전거·보행 겸용로 1.0, 공원 내 도로 1.3, 계단 1.5, 공원 내 진입로(driveway) 1.6, 흙길 ×1.6, 산책로(path) 2.5, 주차장 통로 5
3. 방면마다 **경유점**을 둔다 (`VIA`). 경유점은 브이월드 항공영상에서 넓게 포장된 주 동선을 보고 찍었다.
   - A (올림픽공원역 3번 출구): 체조경기장 남동쪽 광장 → 넓은 보행로 → 역
   - B (한성백제역 2번 출구), C (몽촌토성역 1번 출구): 핸드볼경기장 북쪽 광장 → 중앙 산책로 → 한성백제박물관 북쪽 → (B) 남쪽 / (C) 평화의광장
4. 결과: 점 20개, 길 토막 20개 (역 출입구 계단 3개 포함). 경로 그림은 `geo/osm/render-preview.mjs`로 확인한다.

**공연장 출구**: 체조경기장 둘레의 남·동·서 3곳, 출구별 비율은 1/3씩(가정). 좌석배치도(52구역 14,151석)는 있으나 구역별로 어느 게이트로 나가는지 공개 자료가 없어 나누지 못했다.

## 3. 길 폭 (network.json `widthM`)

방법 (`geo/width/make-sheets.py`, 판독 기록 `geo/width/readings.json`, 반영 `geo/width/apply-readings.mjs`):

1. 길 토막마다 20·50·80% 지점에서 길과 수직으로 1m 눈금자를 그린 항공영상 조각을 만든다 (해상도 약 0.24m/픽셀).
2. 브이월드(봄)와 Esri(가을)를 함께 보고 **토막 안에서 가장 좁은 곳**의 포장 폭을 읽는다.
3. 유효 폭 = 전체 폭 − 장애물 − 측방 여유(벽·화단·주차 차량 등 경계가 있는 쪽마다 0.3m).
4. 광장처럼 20m를 넘는 곳은 병목이 아니므로 20m로 상한을 둔다.
5. 확신도: 상(경계가 뚜렷) / 중(일부 가려짐) / 하(대부분 나무·지붕에 가려 추정).

| 구분 | 토막 | 유효 폭 |
|---|---|---|
| 광장 (상한) | e-02, e-05, e-06, e-13, e-16, e-17 | 20m |
| 광장 가장자리 | e-03, e-10 | 15m |
| 체조경기장 옆 통로 | e-14, e-15 | 7.4m |
| 역 앞 보도·주차장 통로 | e-04, e-11 | 5.9m |
| 횡단보도 | e-01 | 5.0m |
| 숲·박물관 옆 산책로 (확신도 하) | e-07, e-08, e-09, e-12 | 3.4~4.4m |
| 역 출입구 계단 (판독 불가) | e-station-a/b/c | 3.0m (가정) |

- 기존 기본값(3~4m)보다 공연장 주변은 훨씬 넓다. 실제 병목 후보는 **횡단보도, 숲 구간 산책로, 역 출입구 계단**이다.
- 역 출입구 계단은 지붕에 가려 항공영상으로 잴 수 없다. 국토교통부 「도시철도 정거장 및 환승·편의시설 설계 지침」(2025.5) 3.3.2 외부계단 설치 기준은 **중량전철(5·8·9호선 해당) 최소 유효폭 3m 이상**(부득이하면 2m, 에스컬레이터 병행 시 1.5m)이다 (p.32). 그래서 최소 기준인 3.0m를 썼다. 실제 계단은 이보다 넓을 수 있어 대기를 크게 보는 쪽(보수적)이다. 아래 민감도에서 결과를 가장 크게 바꾸는 값이라 실제 폭을 알게 되면 바로 바꾼다.
- 줄 설 공간 `queueAreaM2` = 유효 폭 × min(40m, 토막 길이). 계단은 150㎡.

## 4. 주차장·차량 출구 (parking.json)

- 주차장: P1·P2·P4~P7(대수는 기존 값 유지). 기관 혼잡도 데이터에는 P1A·P1B·P2·P4~P11이 있고 **P3는 없다** → P3는 운영하지 않는 것으로 본다. P8~P11(테니스장 등)은 체조경기장에서 멀어 제외했다. P1A·P1B는 P1 하나로 묶었다.
- 출구 처리량: 2024년 7월 공연일 7일의 출차 기록에서 공연 직후 **10분 최대 평균 출차는 분당 15.6~27.3대**(중앙값 20.5), 평소 날은 11~15대였다. 출구 구분이 없는 데이터라, 가장 붐빈 날의 27대를 공원 전체 처리량으로 보고 각 출구가 맡은 주차면 수 비율로 나눴다 → 북2문 11.0, 동2문 8.9, 남2문 7.2대/분 (가정).

## 6. 검증

### ① 실제 방면 비율 (지하철 승차)
2023~2025년 KSPO DOME 공연 70건(공연 신호가 약한 날 제외)에서, 공연일 3개 역 승차가 평소(같은 달·같은 요일 종류, 공연 없는 날 중앙값)보다 늘어난 양의 비율:

| 방면 | 중앙값 | 사분위 범위 |
|---|---|---|
| A 올림픽공원역 | **93%** | 85~97% |
| B 한성백제역 | 3% | 2~6% |
| C 몽촌토성역 | 4% | 1~9% |

- 지금 `prediction.json` 목업(A 72%, B 19%, C 9%)보다 A 쏠림이 훨씬 크다. **팀원 A의 방면 비율 예측에 반영할 것.**
- 한계: 일별 합계라 공연 시간대만 떼어 보지 못했고, 버스·도보·차량 귀가는 빠져 있다.
- 재현: `python3 geo/validate/subway_check.py --daily '<월별 CSV>/*.csv'` (공연 날짜·관객 수: `geo/validate/kspo-dome-events.csv`, 공연명 없음)

### ①-2 역 도착 시간 폭 (시간대별 승차)
서울교통공사 시간대별 승하차(2025, 1~8호선만 있어 **올림픽공원역 5호선만** 사용)로 공연일 15시 이후 승차 증가분이 몇 시간에 몰리는지 봤다 (공연일 97일).

| | 실제 (중앙값) | 계산 (퇴장 22분, 현재 목업) | 계산 (퇴장 60분) | 계산 (퇴장 80분) |
|---|---|---|---|---|
| 가장 붐빈 1시간에 몰린 비율 | **75%** | 89% | 78% | 71% |
| 상위 2시간 | **95%** | 100% | 99% | 97% |

- 계산 쪽도 실제처럼 '시 단위'로 묶었다 (종료 시각이 시 사이 어디든 올 수 있다고 보고 0~59분 평균). `geo/validate/arrival-window.test.ts`
- 가장 붐빈 시간대는 토요일 21~22시, 일요일 20~21시, 금요일 22~23시가 많았다.
- **실제 귀가는 지금 목업(공연장에서 22분 안에 95% 퇴장)보다 넓게 퍼진다.** 퇴장이 60~80분에 걸친다고 보면 실제와 비슷하다. 굿즈 구매, 대기, 식사 등으로 바로 귀가하지 않는 관객이 있어서로 보인다.
- 재현: `python3 geo/validate/subway_check.py --hourly <시간대별 CSV>`

### ② 민감도 (`pnpm vitest run -c geo/validate/vitest.config.ts`)
공연 A 시연 시나리오(안내요원 6명)로 값을 흔들어 현재 운영안과 분산안을 비교했다. 결과 원본: `geo/validate/sensitivity-result.txt`.

| 경우 | 현재 최대 대기 | 분산 최대 대기 | 부담 감소율 |
|---|---|---|---|
| 기준값 | 1,002 | 778 | 10% |
| 모든 폭 −20% | 974 | 714 | 15% |
| 모든 폭 +20% | 625 | 625 | 9% |
| 역 계단 2.5m | 1,129 | 712 | 13% |
| 역 계단 4m | 279 | 279 | 11% |
| 비 (0.85) | 988 | 831 | 13% |
| 비 (0.7) | 1,019 | 868 | 18% |
| 위험 밀도 0.46㎡ (이전 값) | 1,207 | 483 | 11% |
| 관객 +10% | 1,030 | 930 | 12% |
| 안내 반응률 0.4 | 1,002 | 778 | 10% |
| 퇴장 60분 (정점 15분) | 0 | 0 | 10% |
| 방면 비율 A93·B3·C4 (지하철 실측) | 1,585 | 726 | 23% |

- **12개 경우 모두 분산안의 부담(대기+추가 보행+차량 대기)이 현재안보다 작다** → 결론은 폭·가정값 오차에 강하다.
- 단, **퇴장이 60분에 걸쳐 퍼지면 지금 길 데이터로는 줄이 생기지 않는다**(최대 대기 0). 실제 귀가 혼잡은 역 지상 출입구보다 **역 안(개찰구·승강장·열차 용량)**에서 생길 가능성이 크다. 역 안 처리 능력을 계산에 넣을지 검토가 필요하다.
- 실측 방면 비율(A 93%)을 넣으면 현재안의 A 쏠림이 커져 최대 대기 1,585명, 분산안 효과는 23%로 커진다.
- 결과를 가장 크게 바꾸는 값은 **역 출입구 계단 폭**이다(최대 대기 279~1,129명). 지금은 설계 지침 최소값 3m라 대기를 크게 보는 쪽이다.

## 7. 한계와 다음 할 일

1. 길 폭은 항공영상 판독값이다. 특히 확신도 "하"인 숲 구간(e-07·e-08·e-09·e-12)과 역 계단 3곳은 로드뷰나 현장 확인이 있으면 바로 바꾼다 (`geo/width/readings.json` 수정 → `node geo/width/apply-readings.mjs`).
2. 공연장 출구 비율은 1/3씩 가정이다. 게이트별 좌석 배정 자료가 있으면 교체한다.
3. 차량 출구 처리량은 출구 구분이 없는 데이터로 나눈 값이다. 2025년 입출차(전체구역) 데이터(주차구역 포함)를 받으면 출구별로 다시 구한다.
4. 방면 비율 검증은 일별 데이터다. 시간대별 승하차를 쓰면 종료 직후만 볼 수 있다.
