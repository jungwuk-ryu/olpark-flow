# 올림픽공원 전체 경로 영상 판독

조사 2026-11-22~23. 팀원 B. **현장 실측이 아니라 지도 좌표·영상에서 얻은 가정 자료**다. `map.html`을 브라우저로 열면 구간을 선택하거나 검색하고 지도·거리뷰로 이동할 수 있다. 인터넷 없이 구간 지도와 결과를 볼 수 있다.

## 결과

- 공원 경계 안 **240개 구간**을 추출했다. 이 중 2개는 광장 면의 외곽선이다. 이를 제외한 **238개 선형 구간의 수평 길이 합은 31,569.1m**다. OSM 원본 길 238개가 경계에서 잘려 240개 부분이 되었다. 이는 서로 다른 길의 중심선 길이 합이며 공원의 모든 실제 길을 빠짐없이 찾았다는 뜻은 아니다.
- 각 구간 20/50/80% 지점, **720개 위치를 VWorld·Esri 두 영상으로 대조**했다. 면 외곽선 표본은 폭 판독에서 제외했다. 507개 위치에서 폭 범위 또는 하한을 기록했다.
- **130개 구간**은 3개 표본 모두 폭 범위를 기록했다. **56개**는 일부만, **9개**는 하한을 포함해 기록했다. **43개**는 모두 미확정이며 **2개**는 면 외곽선이다. 따라서 폭 정보가 일부라도 있는 선형 구간은 **195개**다. 3표본 판독도 전체 구간의 최소폭 확인을 뜻하지 않는다.
- OSM 폭 태그는 **16개 구간**에 있다. 영상 판독과 별도 열로 보존했으며 현재 실측으로 승격하지 않았다.
- 기존 계산 경로 **20개**도 별도로 재검토했다. e-01·e-04는 구간마다 **20개 추가 표본**을 대조했다. 기존 `src/data` 숫자는 유지했다. `core-audit.json`에 재확인하지 못한 값을 명시했다.

## 측정 방법과 오차

1. [공식 OSM map API](https://api.openstreetmap.org/api/0.6/map?bbox=127.109,37.509,127.141,37.533)의 XML을 내려받았다. 공원 relation 6185423의 경계 way 26254164 안으로 길을 기하학적으로 잘랐다. 보행로·산책로·계단·자전거길·공원 서비스도로를 포함하고 명시적인 보행 금지·사유 통행은 제외했다. `access=destination` 등 조건부 통행은 태그를 보존했으며 누구나 공연 후 이용 가능한 길이라고 보증하지 않는다.
2. 경위도 차이를 지역 평면으로 변환해 중심선 수평 길이를 계산했다. 경사 길이·계단 실제 보행 거리가 아니다. 소수점 한 자리는 저장 정밀도이며 0.1m 정확도 주장이 아니다. 원본 중심선 오차·미등록 길·중복 및 병렬 노선 가능성은 남는다.
3. Web Mercator z19 영상에서 진행 방향에 수직인 1m 눈금자를 얹었다. 위도 37.519°에서 원본 픽셀은 약 **0.237m**다. 표본당 32×32m 영역을 240×240px로 회전 표시했다. 확대·보간은 원영상 해상도를 높이지 않는다. 표본 좌표는 `survey.json`에 있다.
4. 두 영상의 경계·계절 차이를 사람이 대조해 **대략적 범위**를 기록했다. 예: 2~4m. 범위는 통계적 신뢰구간이나 보장 오차가 아니다. 광장은 `20m 이상`처럼 하한만 둔다. 나무 사이에서 경계가 추측되는 정도이면 `null`로 둔다. 촬영일 메타데이터를 확보하지 못했으므로 봄·가을·특정 연도로 확정하지 않았다. 두 서비스가 독립 촬영 자료라는 보장도 없다.
5. 범위는 물리적 포장 또는 보이는 길 폭이다. 가로수·난간·임시 펜스·주차차량·측방 여유를 모두 뺀 **유효폭이 아니다**. 서비스도로·주차장 차로는 차도 폭이며 보행 전용 용량으로 사용할 수 없다. 확신도는 모두 `하`, `source`는 `가정`, 엔진용 단일 `widthM`은 모두 `null`이다.
6. 세 지점 사이의 좁은 곳, 급곡선, 교차부, 야간 통제, 경사·단차는 별도 확인 대상이다. `min(세 표본)`을 구간 최소폭으로 자동 적용하지 않는다. 숲 아래 길이 실제로 없다는 뜻도 아니다.

[공식 공원 종합안내도](https://www.ksponco.or.kr/olympicpark/map/img/olpark/%EC%98%AC%EB%A6%BC%ED%94%BD%EA%B3%B5%EC%9B%90_%EC%A2%85%ED%95%A9%EC%95%88%EB%82%B4%EB%8F%84.pdf) 1쪽을 렌더해 주요 시설·산책로 배치를 대조했다. 안내도는 축척 도면이 아니어서 폭을 재는 자로 쓰지 않았다. 주요 길은 보이지만 미등록 샛길까지 포함한 완전성 검증은 할 수 없다.

### 공연장 출입문

[공식 대관·시설자료](https://ksponco.or.kr/menu.es?mid=a10405050100)의 [1층 평면도](https://ksponco.or.kr/attachFiles/download/kspo/popimg_acro_1f.pdf), [2층 평면도](https://ksponco.or.kr/attachFiles/download/kspo/popimg_acro_2f.pdf)를 각 1쪽 렌더해 확인했다. 1층에는 1-1/1-2/1-3문과 별도 피난출입구, 2층에는 2-1/2-2/2-3문이 표시된다. 현재 네트워크의 남·동·서 세 출구가 이 문들과 일대일 대응한다고 확인된 것은 아니다.

1층 도면의 분장실2·3 면적은 각각 34.81㎡다. 벽 중심선 다각형 픽셀 면적으로 축척을 두 번 보정하면 **0.09744 / 0.09586m/px**다. 이 축척과 문설주 후보점을 사용하면 **1-1문 3개 병렬 문 묶음의 전부 개방 시 도면상 합계는 약 10~16m**로 추정된다. 문틀·실제 개방·내부 합류 병목을 확인한 값은 아니다. 방풍실 앞뒤의 직렬 문을 중복 합산하지 않았다. 1-2·1-3문은 문 기호·벽·차량 진입구 연결 때문에 확정하지 않았다. 2층도 치수 미확정이다.

`plan_calipers.json`에 방 다각형·면적·문 단면 픽셀을 남겼고 `measure_plan.py`로 다시 계산한다. ±20%는 도면 판독 불확실성을 드러내는 임의 범위이며 검증된 오차 한계가 아니다. PDF 생성 시점은 2018년으로 현재 준공 상태도 보증하지 않는다. 방풍실 표의 2,350·2,400 같은 숫자를 문 폭으로 사용하지 않았다. 공식 3층 PDF·SKP·DAE 링크는 오류 페이지를 반환해 사용할 수 없었다.

## 팀원 A·C에게

- 이 자료를 모델의 단일 유효폭으로 자동 적용하지 않는다. 기존 3m·5.9m·5m를 확인된 값으로 소개하지 않는다.
- 먼저 실제 문→지상 동선→역 3·4번 출입구→계단·에스컬레이터 연결을 맞춘다. 이후 구간을 나누고 병목 단면의 유효폭·운영 방향·개방 수를 입력한다.
- 미확정 구간을 폭 0으로 채우지 않는다. 현재 가정을 유지한 민감도 시나리오와 확인된 구조를 구분한다. 정확한 계단·문 폭과 공연일 개방 상태는 준공도면·운영 자료가 있어야 보강된다.

## 미확정 43개 구간의 임시 폭 보완

추가 요청에 따라 폭이 모든 영상 표본에서 미확정인 **43개 구간**에 사용할 임시 포장 폭을 [별도 CSV](assumed-widths.csv)와 [JSON](assumed-widths.json)에 채웠다. 원본 판독 상태는 유지한다. 5개는 기존 OSM 폭 태그를 가정으로 차용했고, 38개는 길 종류별 초기값을 적용했다. 기준은 보행로·자전거길 3m, 산책로·계단 2m, 서비스도로 6m다. 실제 측정에서 얻은 평균값이나 설계 기준이라는 뜻은 아니다.

결과는 3m 32개, 2m 5개, 6m 5개, OSM 태그 1m 1개다. 각 항목의 `source`는 `가정`, `measured`는 `false`다. 민감도 검사를 위한 0.5~1.5배 범위를 함께 두었으며, 보행 유효폭은 장애물·측방 여유가 미확인이라 `null`로 유지했다. 서비스도로 폭을 사람 전용 처리량으로 바로 변환하지 않는다. 길의 존재·행사 후 개방 가능성·중심선 정확성도 추가 확인 대상이다.

재현: `python3 geo/width/park-survey/fill_assumptions.py`. 기존 엔진 20개 경로에는 이미 가정값이 있으므로 이번 보완표를 자동 덮어쓰지 않는다. 부분 판독 56개 구간은 원래 표본 범위를 참고하되, 가려진 구간까지 최소폭이 확인된 것으로 해석하지 않는다.
