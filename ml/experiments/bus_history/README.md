# 버스 정류장 일별 승차 이력을 이용한 Chronos-2 후향 시험

2025년 11월 1일~12월 31일, 전날 오후 5시에 예측하는 조건에서 Chronos-2의 오차는 **정류장당 하루 평균 39.79건**이었다. 그때까지 사용할 수 있는 같은 이력으로 구한 요일 중앙값은 **42.77건**이었다. 서울시 일자료가 안내된 일정대로 공급되고 이를 매일 저장했다는 조건의 결과다. 이미 열람한 두 달 자료를 사용한 별도 연구이며 운영 모델을 고르는 평가에는 넣지 않았다.

## 같은 854개 정류장·날짜에서 얻은 결과

| 기간 | 날짜 / 정류장·일 | 관측 승차 건수 | 같은 이력 요일 중앙값 MAE | Chronos-2 P50 MAE | 요일 중앙값 WAPE | Chronos-2 WAPE |
|---|---:|---:|---:|---:|---:|---:|
| 11월 | 30 / 420 | 219,158 | 38.66 | 34.93 | 7.41% | 6.69% |
| 12월 | 31 / 434 | 229,512 | 46.74 | 44.50 | 8.84% | 8.41% |
| 전체 | 61 / 854 | 448,670 | 42.77 | 39.79 | 8.14% | 7.57% |

MAE는 정류장·수송일별 절대 승차 오차를 평균한 값이다. WAPE는 같은 행의 절대오차 합을 관측 승차 합으로 나눴다. Chronos-2는 날짜별로 14개 정류장의 절대오차를 합산하면 37/61일, 정류장별로 두 달을 합산하면 12/14곳에서 오차가 작았다. 두 모델의 WAPE 차이는 **0.57%p**, 7일 이동 블록 부트스트랩 95% 구간은 **−0.03~1.17%p**다. MAE 차이 2.98건의 같은 구간은 −0.14~6.28건이다. 61일 내 변동 폭을 고려하면 우위의 방향까지 확정하기 어렵다. 같은 날짜의 14곳을 함께 유지하고 연속된 날짜 7개씩 복원 추출했다. 반복은 4,000회, 시드는 20261123이다. [전체·정류장별 결과](results.json)

Chronos-2가 출력한 P10~P90에 실제 승차가 포함된 비율은 80.68%였고 평균 폭은 119.18건이었다. 11월에는 84.29%, 12월에는 77.19%였다. 별도 구간 보정은 수행하지 않았다. 각 정류장·날짜의 두 기준선과 P10·P50·P90, 관측값, 예측 시점, 최신 입력 수송일을 남겼다. [854개 예측과 정답](predictions.csv)

## 승차 정의와 원자료 대조

서울시 일자료의 노선·정류장별 **교통카드 승차 건수**를 수송일과 방향별 ARS 번호로 합산했다. 환승할 때 발생한 승차도 포함한다. 이 합계에는 평소 버스 이용과 공연 관련 이용이 함께 들어 있다. 개인별 공원 퇴장, 특정 공연의 관객, 시간대별 버스 유입을 이 실험으로 분해할 수는 없다. STCIS에서 선택한 고정 정류장 번호만 이용했고 시간대 관측은 모델에 넣지 않았다. [서울시 집계 정의](https://data.seoul.go.kr/dataList/OA-12912/A/1/datasetView.do)

- 대상 ARS는 24123, 24127, 24211, 24221, 24222, 24231, 24233, 24239, 24240, 24241, 24244, 24245, 24246, 24396이다. 각 ARS는 서울시 표준 정류장 ID 하나와 대응한다.
- 서울시 월별 12개 CSV의 전체 14,940,136행을 읽고 이 정류장의 23,183행을 추렸다. 수송일·노선번호·노선명·표준 정류장 ID·ARS·정류장명·승하차·등록일이 정제본과 전부 일치했다. 수송일·ARS·짧은 노선번호만으로 중복 제거하면 서로 다른 운행 변형 931행을 잃는다. 원본의 변형 행을 모두 유지했다.
- 14곳 모두 365일이 있어 5,110개 정류장·일의 관측값을 얻었다. 대상 행의 등록일·승하차에 빈칸은 없었다. 서울시 파일에서 노선 자체가 빠진 경우의 무운행·무거래·수집 누락 여부는 이 대조로 판별할 수 없다. [원본 대조 코드](audit.py)

## 기준시각과 비교 방법

1. 서울시 행 23,183개의 등록일은 모두 수송일의 3일 뒤였다. 각 정류장·일에서 가장 늦은 노선 등록일을 구하고, 시각이 없는 등록일의 **다음 날 00:00 KST**부터 합계를 허용했다. 목표일 D의 예측은 D−1 17:00에 발행하므로 최근 이력은 **D−5**다. 예를 들어 11월 1일을 예측할 때 10월 31일 17시에 허용된 마지막 수송일은 10월 27일이었다.
2. 기초 학습기간은 1월 1일~8월 31일의 243일, 3,402개 정류장·일로 고정했다. 기간 마지막 정답은 등록일 규칙상 9월 4일 00:00에 열린다. 이 구간에서 고정한 정류장·요일 중앙값을 추가로 기록했다. 11~12월 MAE 46.04건, WAPE 8.76%다.
3. 주 비교에서는 두 방법에 **같은 시점에 허용된 1월 1일 이후의 전체 이력**을 넘겼다. 9~10월과 시험기간 중 앞선 날짜도 각 예측 시점에 이미 등록된 관측만 이력에 추가했다. 9~10월 성적으로 하이퍼파라미터를 고르지 않았다. 요일 기준선은 정류장별로 목표일과 요일이 같은 관측의 중앙값이다. Chronos-2는 정류장마다 300~360일의 단변량 이력에서 5일을 내다보고 마지막 날의 P50을 사용했다. 외부 공변량과 정류장 간 학습은 사용하지 않았다. 종합 점수는 모든 예측을 마친 뒤 정답을 결합해 계산했다. [예측·평가 코드](run.py)
4. 가중치 리비전은 `29ec3766d36d6f73f0696f85560a422f50e8498c`, 추론 코드 리비전은 `1224fafa91e1ecd6674f5204066b159e40b5e4a1`이다. 모델 파라미터 119,477,664개를 그대로 사용했다. 가중치 파일 SHA-256은 `ddcda3c7508bf2528087723e98a20707cc04b7f370ae275a9fd88078ddba4f42`다. 같은 가중치와 설정 파일은 첫 예측 시점보다 앞선 2025년 10월 30일 UTC의 공식 리비전에도 게시돼 있다. 이번 시험은 2026년에 해당 코드로 실행한 소급 평가다. [공식 모델 카드](https://huggingface.co/amazon/chronos-2/blob/29ec3766d36d6f73f0696f85560a422f50e8498c/README.md) · [가중치 최초 게시본](https://huggingface.co/amazon/chronos-2/tree/95a9710e2596287d08352589f42634fa5abdf0a7) · [공식 추론 코드](https://github.com/amazon-science/chronos-forecasting/blob/1224fafa91e1ecd6674f5204066b159e40b5e4a1/src/chronos/chronos2/pipeline.py)

## 서울시 배포 주기와 적용 조건

서울시는 Sheet에 최근 25일치를 제공하고 매일 3일 전 자료를 적재한다고 안내한다. 과거 파일은 월 단위이며 2025년 각 월 파일의 표시 수정일은 이듬달 5일이다. 등록일 다음 날 00:00은 **일별 공개 경로를 매일 성공적으로 수집했을 때 쓸 수 있는 이력의 상한**이다. 2025년 당시의 실제 수신시각·누락 페이지·후일 정정 전 버전은 현재 월별 파일에 기록되어 있지 않다. 월 파일의 표시 수정일 다음 날 00:00을 적용하면 11~12월 D−1 17시에서 최신 수송일까지의 예측 거리는 **7~37일**이다. 위 5일차 성능을 이 월별 배포 조건에 적용하려면 해당 시차로 다시 시험해야 한다. [서울시 일자료 안내와 월별 파일 수정일](https://data.seoul.go.kr/dataList/OA-12912/A/1/datasetView.do)

현장에 적용할 때는 일자료의 전체 페이지 수신 완료시각과 버전을 저장하고, 각 예측 시점까지 실제 도착한 이력으로 마지막 수송일과 예측 거리를 계산해야 한다. 이번 실험으로 평가한 거리는 5일뿐이다. 계속 수집하지 않으면 25일 일별 조회 범위가 지나고 월 파일을 기다려야 할 수 있다.

## 재현

`ml/`에서 아래 명령을 실행한다. 관측 입력은 기존 `data/` 파일이다. 별도 임시 경로에 Python 3.12 환경과 공개 가중치만 내려받는다. 실행 때 가중치와 설정의 SHA-256, 로컬 자료 매니페스트에 기록된 입력 14개 파일의 SHA-256을 확인한다. Apple Silicon CPU에서 4스레드로 실행한 한 번의 측정에서 61개 예측시점의 루프는 4.78초, 원본 대조와 프로세스 시작을 포함한 전체는 20.95초, 최대 RSS는 0.90 GB였다. [실행환경](requirements.lock)

```sh
exp_dir=$(mktemp -d)
python3.12 -m venv "$exp_dir/venv"
"$exp_dir/venv/bin/python" -m pip install -r experiments/bus_history/requirements.lock
"$exp_dir/venv/bin/hf" download amazon/chronos-2 config.json model.safetensors \
  --revision 29ec3766d36d6f73f0696f85560a422f50e8498c --local-dir "$exp_dir/weights"
HF_HUB_OFFLINE=1 PYTHONDONTWRITEBYTECODE=1 "$exp_dir/venv/bin/python" experiments/bus_history/run.py \
  --weights-dir "$exp_dir/weights" --output-dir "$exp_dir/results"
cmp experiments/bus_history/predictions.csv "$exp_dir/results/predictions.csv"
```

같은 격리 환경에서 전체 시험을 두 번 실행해 예측 CSV와 결과 JSON이 각각 바이트 단위로 일치했다. 별도 검산으로 854행의 기준시각·관측값·이력 길이·두 중앙값과 전체 MAE·WAPE를 다시 계산했다. 80% 구간에 포함된 관측은 689행이다. 실행 결과에는 라이브러리·Python 버전과 입력 해시가 남는다. 장비와 수치 라이브러리가 다르면 부동소수점 끝자리가 달라질 수 있다.
