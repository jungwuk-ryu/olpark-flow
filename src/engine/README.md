# 계산 엔진 (`src/engine`)

UI와 분리된 순수 TypeScript. 입력 파일 모양은 `docs/data-contract.md`를 따른다.

| 파일 | 하는 일 |
|---|---|
| `egress.ts` | 퇴장 곡선. 총 퇴장 시간(95%가 나오는 시각)·정점 시각 → 감마 분포 모수 → 분 단위 비율 (합 = 1) |
| `simulate.ts` | 1분 단위 보행 흐름: 출구 → 방면 분배(안내 × 반응률) → 걷는 지연 → 병목 대기 → 줄 번짐 → 교차점 |
| `vehicle.ts` | 차량 출구 대기 (출구별 줄 하나) |
| `optimize.ts` | 분산안 격자 탐색 (안내 비율 × 시작 시각 × 차량 출구 배정) |
| `status.ts` | 상태 색: 여유 / 보통 / 병목 / 위험 |

## 핵심 규칙

- 시간: 배열 t번째 = 종료 후 t~t+1분. 대기 인원은 그 1분이 끝난 시점 값. `maxQueueMinute`, `clearMinute`는 "종료 후 몇 분"으로 보고한다.
- 병목 용량 = 유효 폭 × 폭 1m당 분당 통과 인원(통로 82 · 문 115 · 계단은 통로의 60%) × 날씨 보정. 숫자는 `assumptions.json`.
- 대기(t) = 대기(t−1) + 도착(t) − 통과(t), 통과(t) = min(대기 + 도착, 용량). 같은 길을 쓰는 무리끼리는 (대기 + 도착) 비율로 나눈다.
- 줄 번짐: 다음 길의 대기가 `queueAreaM2 ÷ 0.46㎡`를 넘지 않게 이번 길 통과량을 줄인다. 걷는 중인 사람은 한계에 넣지 않는 근사.
- 교차점: 직전 1분에 차량이 있었으면 보행 용량 × 60%, 보행자가 있었으면 차량 처리량 × 40%.
- 차로 가는 관객(차량 비율)은 지하철 방면 보행에서 빠진다. 주차장까지 걷는 시간(`walkToLotMinutes`)만큼 늦게 출차한다.
- 우회 추가 보행 = 각자 간 방면의 보행 시간 − 그 출구에서 가장 가까운 방면의 보행 시간. 현재 운영안에서도 0이 아닐 수 있다.
- **안내요원은 길 용량을 늘리지 않는다.** 동시에 운영할 분기점 수(안내요원 ÷ `staffPerJunction`)만 제한하고, 효과는 안내 반응률로만 들어간다.
- 분기점이 여러 곳이면 한 곳씩 차례로 정하는 탐욕적 탐색이다.
